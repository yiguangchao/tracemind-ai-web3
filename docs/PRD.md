# AI Web3 Transaction Explainer 需求文档（PRD）

## 项目定位

一个面向 Web3 新手、开发者和 AI × Web3 共学营学员的链上交易解释与安全确认助手。用户输入测试网交易哈希、合约地址或合约交互信息后，系统读取链上数据，并用 AI 生成中文解释、风险提示、人工确认清单和 Markdown 学习记录。

## 项目背景

在 Web3 学习和开发过程中，新手常常看不懂钱包弹窗、交易哈希、区块浏览器、Gas、合约调用、事件日志和授权行为。很多用户只知道“点确认”，但不知道自己到底授权了什么、交易是否成功、Gas 消耗在哪里、合约写入是否存在风险。

AI 可以帮助用户把复杂的链上信息翻译成自然语言说明；Web3 可以提供公开、可验证的链上交易记录。这个项目的核心价值是把两者结合起来：

链上数据读取 + AI 解释 + 风险提示 + 人工确认 + 学习记录沉淀

本项目不做自动转账、不做自动签名、不接触私钥或助记词。AI 只负责解释、总结、提示风险和生成记录，所有高风险动作都必须由用户人工确认。

## 项目目标

### 总目标

构建一个可以部署到 GitHub / Vercel 的 Web3 工具型项目，帮助用户理解测试网交易和合约交互，并形成可提交到学习 repo 的实验记录。

### 具体目标

1. 支持用户输入交易哈希并查询链上基础信息。
2. 展示交易状态、发送方、接收方、金额、Gas、区块高度、交易类型等信息。
3. 调用 AI 对交易内容进行中文解释。
4. 根据规则判断交易风险等级。
5. 生成“人工确认清单”。
6. 生成 Markdown 格式学习记录，方便保存到 GitHub repo。
7. 明确安全边界：不读取、不存储、不上传用户私钥或助记词。
8. 后续可扩展到合约地址解释、ABI 解释、钱包弹窗解释、测试网部署记录生成。

| 用户类型 | 需求 | 使用场景 |
|---|---|---|
| Web3 新手 | 看懂交易哈希、Gas、钱包确认含义 | 学习测试网交互、提交实验报告 |

## 核心使用场景

### 场景 1：用户解释一笔测试网交易

用户在 Sepolia 上完成一笔测试交易，复制交易哈希到系统中。系统查询交易信息，展示交易是否成功、from、to、value、Gas、区块高度，并调用 AI 解释这笔交易的含义。

### 场景 2：用户生成实验记录

用户完成一次合约写入后，希望把过程写进 GitHub repo。系统根据交易信息生成 Markdown 学习记录，包括基本信息、AI 解读、风险检查、我的理解、区块浏览器验证项。

### 场景 3：用户判断交易风险

用户准备执行某个合约调用，但看不懂钱包提示。系统可以根据交易数据或调用信息提示：是否涉及转账、是否涉及授权、是否为合约写入、是否需要人工确认。

### 场景 4：课程项目展示

用户把本项目作为 AI × Web3 工具项目提交，README 中展示项目目标、技术栈、功能截图、示例交易、风险边界和后续计划。

## 产品范围

### MVP 范围

MVP 只做“交易哈希解释器”。

必须支持：

- 输入交易哈希。
- 选择网络，至少支持 Sepolia。
- 查询交易基础数据。
- 查询交易 receipt。
- 展示交易状态。
- 展示 from、to、value、gasUsed、effectiveGasPrice、blockNumber。
- 展示是否成功、是否为合约调用、是否有 value 转账。
- 调用 AI 生成中文解释。
- 生成风险检查结果。
- 生成 Markdown 学习记录。
- 提供复制 Markdown 按钮。

### 非 MVP 范围

第一版不做：

- 不做真实主网交易执行。
- 不做自动签名。
- 不做自动转账。
- 不做自动 approve。
- 不做私钥托管。
- 不做 DeFi 自动交易。
- 不做钱包资产管理。
- 不做链上身份系统。
- 不做复杂数据库。

### 后续扩展范围

后续可以增加：

- 合约地址解释。
- ABI 函数解释。
- input data 解码。
- ERC-20 approve 风险识别。
- ERC-20 transfer 识别。
- NFT mint / transfer 识别。
- 多网络支持：Base Sepolia、Arbitrum Sepolia、Optimism Sepolia。
- 钱包连接，但只用于展示当前地址，不自动执行交易。
- 示例交易库。
- 本地历史记录。
- 导出 PDF 或生成 GitHub issue。

## 功能需求

### 首页 / 输入页

用户进入页面后，可以选择网络并输入交易哈希。

页面元素

- 项目标题：AI Web3 Transaction Explainer
- 项目说明：输入测试网交易哈希，获取 AI 中文解释和风险提示。
- 网络选择器：Sepolia、Base Sepolia 等。
- 交易哈希输入框。
- 查询按钮。
- 示例交易哈希按钮。
- 安全提示：本工具不会要求输入私钥或助记词。

验收标准

- 用户可以输入合法 0x 开头交易哈希。
- 非法格式应提示错误。
- 查询中显示 loading 状态。
- 查询失败显示明确错误信息。

### 链上数据展示模块

展示交易原始数据和交易回执信息。

展示字段

| 字段 | 说明 |
|---|---|
| network | 当前查询网络 |
| hash | 交易哈希 |
| status | success / reverted / pending |
| from | 发送方地址 |
| to | 接收方地址，可能为空，合约部署交易可能为空 |
| value | 转账金额，单位 ETH |
| gas | 交易 gas limit |
| gasUsed | 实际消耗 Gas |
| effectiveGasPrice | 实际 Gas 价格 |
| blockNumber | 区块高度 |
| transactionIndex | 交易在区块中的索引 |
| input | 原始 input data |
| contractAddress | 如果是合约部署，则展示部署出的合约地址 |
| logs count | 事件日志数量 |

验收标准

- 成功展示交易基础字段。
- 交易成功 / 失败状态清晰。
- 地址可复制。
- 交易哈希可跳转区块浏览器。
- 长 input data 默认折叠。

### AI 解释模块

把链上交易数据整理成结构化上下文，发送给 AI，生成中文解释。

AI 输出内容

1. 这笔交易大概在做什么。
2. 交易参与方是谁。
3. 是否涉及 ETH 转账。
4. 是否调用了合约。
5. 是否可能是合约部署。
6. Gas 使用情况如何理解。
7. 交易成功还是失败。
8. 对新手的解释。
9. 需要人工注意的风险点。
10. 不确定项说明。

AI 输出原则

- 不确定时必须说“不确定”。
- 不允许编造合约名称。
- 不允许编造交易目的。
- 如果 input data 无法解码，只能说明“该交易包含合约调用数据，但当前无法确认具体函数”。
- 不输出投资建议。
- 不引导用户转账或授权。

验收标准

- AI 解释必须使用中文。
- AI 解释必须分段清晰。
- AI 解释必须包含“不确定项”。
- AI 不得要求用户输入私钥或助记词。

### 风险检查模块

系统根据规则对交易做基础风险分类。

风险等级

| 等级 | 含义 | 示例 |
|---|---|---|
| 低风险 | 只读查询、无转账、无授权、测试网记录查看 | 查询历史交易 |
| 中风险 | 合约写入、测试网转账、合约部署 | setMessage、mint 测试 NFT |
| 高风险 | 主网资产转移、approve 授权、未知合约交互、大额转账 | ERC-20 approve、swap、bridge |
| 未知风险 | input data 无法解析、合约未知、交易失败原因不明 | 未知 selector |

初版规则

- `value > 0`：提示涉及原生资产转账。
- `to == null` 且 receipt 有 contractAddress：提示可能是合约部署。
- `input != 0x`：提示涉及合约调用。
- `status == reverted`：提示交易失败。
- `logs.length > 0`：提示产生事件日志。
- 网络为主网时：默认提高风险等级。
- 函数 selector 为 `0x095ea7b3`：疑似 ERC-20 approve，高风险。
- 函数 selector 为 `0xa9059cbb`：疑似 ERC-20 transfer，中/高风险，取决于网络和金额。
- 函数 selector 为 `0x23b872dd`：疑似 transferFrom，高风险。
